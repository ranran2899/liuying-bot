面向需要交叉求证的复杂问题，一次调用完成「拆解 → 并发检索 → 去重归并 → 汇总」。

工作流程：

1. 把 question 拆成最多 4 条角度不同的 queries（由调用方给出）
2. 4 路检索并发执行，总超时 25 秒，单路失败由其余路补足
3. 按归一化 URL 去重（忽略协议、www、查询串、尾斜杠），交错取样最多 10 条
4. 交给 LLM 依据材料写结论，明确标注分歧与不确定

为什么优先用它而不是连续调 `web_search`：

- N 次串行 `web_search` = N 轮模型决策 + N 次网络往返
- 本技能把它压成 1 轮，token 与延迟都显著下降
- 交错取样避免某一个子查询占满全部名额

调用边界：

- 每会话配额 2 次，属重型工具，简单事实查询请用 `web_search`
- queries 省略时退化为单路检索，等价于加了摘要的 `web_search`
- 材料不足时会明确说不确定，不会编造

调用建议：

- 子查询要真正换角度（时间、主体、正反评价），不要只换同义词
- 已经拿到结论后不要再调一次「换个说法确认」
