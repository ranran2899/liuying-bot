# plugins.json 索引文件格式说明

插件商店通过 `repo_file_manager.get_file_content(仓库地址, "plugins.json")` 拉取索引文件：

- 原生插件：`https://gitee.com/shiranranran/liuying_bot_plugins/tree/main/plugins.json`
- 第三方索引：`https://gitee.com/shiranranran/liuying_bot_plugins/tree/index/plugins.json`

文件顶层为 JSON 数组，每个元素对应一个插件，字段由 `models.py` 的 `StorePluginInfo`（Pydantic 模型）校验，字段定义如下：

## 字段说明表

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `name` | string | 是 | - | 插件展示名称，支持中文，用于列表展示与按名称安装（如 `添加插件 打工`） |
| `module` | string | 是 | - | 插件模块名，全局唯一，作为安装状态匹配与按 module 操作的键 |
| `module_path` | string | 是 | - | 模块路径，点分格式。单文件插件为模块名本身（如 `打工`→`dagong`）；目录插件为包路径；`is_dir=true` 且值为 `"."` 时表示仓库根目录整体作为一个插件 |
| `description` | string | 是 | - | 插件简介，展示在列表"简介"列 |
| `usage` | string | 是 | - | 插件用法说明文本 |
| `author` | string | 是 | - | 作者名，支持按作者搜索 |
| `version` | string | 是 | - | 版本号。可与已安装版本比对判断是否有更新；支持 `主版本-分支` 写法（如 `0.2-dev`），`-` 后的部分会被当作 Git 分支名用于切换下载分支 |
| `plugin_type` | string | 是 | - | 插件类型枚举值，取值见下表 |
| `is_dir` | boolean | 是 | - | 是否为目录（包）插件。`true` 时下载整个目录，`false` 时只下载 `{module_path}.py` 单文件 |
| `gitee_url` | string \| null | 否 | `null` | 插件的 Gitee 仓库链接（展示/备用） |
| `github_url` | string \| null | 否 | `null` | 插件代码所在仓库地址（`/tree/分支` 形式）。原生插件可省略，缺省时自动使用伴生仓库 `DEFAULT_GITEE_URL`；第三方插件必须填写 |

## `plugin_type` 枚举取值

对应 `liuying/utils/enum.py` 的 `PluginType`（StrEnum，JSON 中填枚举值字符串）：

| 取值 | 含义 | 权限 |
| --- | --- | --- |
| `NORMAL` | 普通插件 | 所有人 |
| `ADMIN` | 管理员插件 | 群管理员 |
| `SUPERUSER` | 超级用户插件 | 超级用户 |
| `ADMIN_SUPER` | 管理员/超级用户插件 | 管理员或超级用户 |
| `DEPENDANT` | 依赖插件 | 受权限控制，hooks 拦截时跳过 |
| `HIDDEN` | 隐藏插件 | 不受权限控制，hooks 拦截时跳过 |
| `PARENT` | 父插件 | 仅作标记 |

## 完整示例

```json
[
    {
        "name": "打工",
        "module": "dagong",
        "module_path": "plugins.dagong",
        "description": "打工赚金币小游戏",
        "usage": "打工: 每天打工获取金币",
        "author": "liuying",
        "version": "0.1",
        "plugin_type": "NORMAL",
        "is_dir": false,
        "gitee_url": null,
        "github_url": null
    },
    {
        "name": "群管日志",
        "module": "admin_log",
        "module_path": "plugins.admin_log",
        "description": "记录群管理操作",
        "usage": "自动记录, 无需手动触发",
        "author": "third-party",
        "version": "1.2-dev",
        "plugin_type": "ADMIN",
        "is_dir": true,
        "gitee_url": "https://gitee.com/xxx/admin_log",
        "github_url": "https://gitee.com/xxx/plugins_repo/tree/main"
    },
    {
        "name": "整包插件",
        "module": "full_pack",
        "module_path": ".",
        "description": "以仓库根目录整体安装的插件",
        "usage": "示例用法",
        "author": "third-party",
        "version": "0.3",
        "plugin_type": "NORMAL",
        "is_dir": true,
        "github_url": "https://gitee.com/xxx/full_pack/tree/main"
    }
]
```

## 安装行为与字段的对应关系

1. `github_url` 为空 → 使用伴生仓库 `DEFAULT_GITEE_URL`。
2. `version` 含 `-` → 按 `-` 切分，后半段作为仓库分支重写 `github_url`（如 `0.2-dev` → `/tree/dev`）。
3. `is_dir: true` → 调用 `list_directory_files` 列出 `module_path` 对应目录的全部文件并批量下载；`is_dir: false` → 仅下载 `{module_path}.py`。
4. 原生插件安装到 `BASE_PATH`，第三方目录插件安装到 `BASE_PATH/plugins/{插件目录}`，第三方单文件插件安装到 `BASE_PATH/plugins/`。
5. 目录内或仓库根目录存在 `requirement.txt` / `requirements.txt` 时自动安装依赖。
6. `-s git` 强制 Gitee 源、`-s ali` 强制阿里云源，不传时第三方默认 Gitee、原生用默认源。
